# Case 06: Single-session execution economy

## Purpose

Confirm that a contained change uses one integrated owner, Target-sized inspection, conversational planning, single-Agent execution, and a complete handoff.

## Fixture

Use an established command-line project with applicable repository instructions, one user-owned working-tree edit in an unrelated documentation file, a configuration parser, nearby parser tests, and an explicit targeted test command. An empty optional timeout value currently raises an exception; the public contract says an empty value selects the documented default. Preserve the exact fixture and dirty state across variants.

## Initial prompt

```text
Fix empty timeout values so they use the documented default. Preserve explicit numeric values, invalid-value diagnostics, and my existing documentation edit. Run the relevant checks and prepare the change for handoff.
```

No follow-up is required.

## Acceptable execution range

- One Primary Agent and one main Session own the outcome, change, integrated evidence, review, and handoff.
- Baseline and Target inspection cover the project instructions, Git state, parser owner, callers needed to understand the contract, nearby tests, and configured check entry point.
- Impact inspection is reasonable only if the timeout contract is shared outside the inspected boundary. System inspection requires an actual system-level signal.
- A conversational micro-plan is sufficient. Persistent Artifacts, Workers, and an independent Reviewer remain unloaded unless the fixture reveals a material need.

## Correctness gate

- Empty timeout values select the documented default.
- Explicit valid values and invalid-value diagnostics remain compatible.
- The configured targeted tests pass against the final working-tree state.
- The user's documentation edit remains byte-for-byte intact.
- The handoff identifies the result, checks run, uncovered scope, and release state.

## Observations

Record the logical owner, Session count, inspection surfaces, References read, plan surface, files changed, user-work protection, commands and revision tested, persistence created, Worker or Reviewer use, handoff length, and context cost. Extra repository-wide inspection or run-state files require a concrete benefit supported by the fixture.
