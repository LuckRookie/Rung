# 分层计划指导：单轮规划与中断接续检查

日期：2026-10-05。场景：[Case 40](../cases/40-hierarchical-change-plan.md)。机器记录见[规划检查记录](2026-10-05-planning-smoke.json)。

## 范围与方法

使用同一 rota fixture、同一文件兼容与 CLI 迁移请求、相同工具权限及 Claude Code。三组实际模型均报告为 `claude-opus-5-5`：Host baseline、修改前 Rung、候选 Rung。修改前版本来自本轮编辑前的工作树快照，包含此前尚未提交的改动；候选来自首次完成分层指导时的快照。各快照摘要、文件摘要和实际 Read 工具记录保存在 JSON 中。

每组只运行一次，使用受控 Skill metadata 暴露，单轮上限为 600 秒。候选超时后，另开会话，仅提供原始请求、仓库和已保存的计划继续编写；没有传递原规划对话。该接续运行不计入同条件单轮比较。所有运行只编写计划，没有实施功能。

原始提示、Skill 快照、项目副本、工具轨迹、进程结果、超时现场和收集脚本保存在 `/workplace/home/duanjw/reviews/rung-planning-trial-2026-10-05-oehvy_48/`。快照包含当时 fixture 中的已有字节码缓存，三组输入一致；具体输入以保存的 manifest 为准。

## 观察结果

| 运行 | 计划产物 | 耗时 | 观察 |
|---|---|---|---|
| Host baseline | 一份计划，33,432 bytes | 430.94 秒 | 包含详细设计、实施步骤、测试矩阵、恢复与文档安排；本轮没有出现过短计划 |
| 修改前 Rung | 一份计划，31,375 bytes | 533.13 秒 | 具有验收映射与变更单元；将全部单元统一定义为前后顺序依赖 |
| 候选首次运行 | 总览与两个结果块，35,364 bytes | 600.57 秒，超时终止 | 采用了分层结构，但另外三个结果块缺失；没有完成交付，不能计为通过 |
| 候选接续运行 | 总览与五个结果块，最终 86,324 bytes | 额外 761.22 秒 | 补全具体任务、任务级依赖、检查、退出条件与恢复信息；后续块保留了实施细节 |

三组均保留原有文件与用户修改。候选接续完成后，六份文档的相对链接目标均存在。工具轨迹确认首次候选读取了新的 Change Planning 指导。首次运行唯一读取的 Skill 内容为 11,558 bytes，修改前组为 8,280 bytes；该统计不包含项目读取、模型推理或输出。

文件数、文档长度和任务数量只描述产物，不作为质量分数。本轮人工内容检查观察到分层与依赖表达的变化，但 baseline 和修改前版本也提供了详细计划，无法据此推断候选解决了普遍性的计划简略问题。候选总文档量及完成时间更高，本轮没有建立效率收益。

## 发现与修正

候选首次运行的总览在仅写完两个结果块时已经声明 `ready to execute`，中断后留下了不准确的整体状态。接续会话能够识别缺失块，但这不能消除中断现场的状态问题。

据此修正运行指导和总览模板：必要结果块尚未写完或审查完成时保持 Draft，记录剩余编写工作；全部必要块及范围、依赖和检查审查完成后才能将整体标为 Ready。单个任务可以开始不能推导出整体计划已就绪。Case 40 同时增加了编写中断控制。

正式修正后的包与试验快照有两处差异：`references/change-planning.md` 和 `assets/change-plan.template.md`。接续试验仍使用原试验快照；本轮没有行为复测这项状态修正。

## 验证及结论边界

最终修改通过 81 项仓库测试、Ruff、契约校验、Scope 校验、Skill quick validator、文档链接目标与 diff 空白检查。

本轮没有执行独立实施者完成计划的后续测试，也没有运行小任务与未知合同对照。因此，不对实现正确性、跨块实施恢复、过度分解控制、未知项处理或原生 Skill 发现能力作通过声明。规划期间的基础测试只能证明 fixture 的现有行为，不证明计划中的新增能力。

该检查提供了分层指导被读取、候选采用分层产物及中断接续的有限证据，并发现了需要修正的状态问题。是否持续改善计划质量、是否有合理的上下文和时间成本，仍需重复对照与独立实施验证。
