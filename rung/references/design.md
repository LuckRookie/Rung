# Stage 3：Design

在确定实现边界、接口或数据方案时读取本文件。

## 目标

形成满足验收条件、符合项目结构且复杂度相称的 Solution Design。

## 执行

1. 从验收条件推导需要新增或改变的行为。
2. 标出稳定边界、受影响模块和职责归属。
3. 定义接口、数据流、状态变化和错误处理。
4. 检查依赖方向、兼容性、迁移与回退需求。
5. 确定单元、模块、集成和端到端验证边界。
6. 对安全、性能、隐私和可维护性风险给出与任务相关的处理方案。
7. 复用项目已有模式，并为新增抽象说明当前变化依据。
8. 将长期影响的架构决定写入 ADR 或项目现有决策记录。

## Artifact

使用 `assets/solution-design.template.md`。Lite 可以用简短结构化设计；Standard 和 Strict 持久化设计及重要理由。

## Design Gate

- 设计覆盖全部验收条件；
- 模块、接口、数据和错误边界清楚；
- 兼容、迁移和回退要求已有处理位置；
- 验证边界能够证明关键行为；
- 设计复杂度与当前问题和项目成熟度相称。

需求或项目事实变化时返回 Clarify 或 Inspect；设计稳定后进入 Plan。
