# Review Card

Read when a diff, structure, risk, evidence, or delivery needs judgment.

## Operate

- Compare outcome, design, plan changes, diff, evidence, and release.
- Judge current correctness and coherence in touched and affected boundaries.
- Check ownership, public surface, dependencies, state, data, errors, compatibility, and durable facts.
- Confirm tests protect behavior, contracts, invariants, and failures without incidental internals.
- Fix authorized ordinary findings; route material findings to their concern.

Use [Software Quality](software-quality.md) for current fitness, [Technical Debt](technical-debt.md) for future burden, [Project Model](project-model.md) for semantic drift, [Engineering Structure](engineering-structure.md) for structure, and [Architecture Assessment](architecture-assessment.md) for system judgment.

Primary Agent reviews; consider an independent reviewer for public contracts, security/privacy, persistent data, architecture, migration, required gates, Harness authority, or user request.

Stop when findings are resolved, routed, or accepted as risk. Output findings, risk, debt, and delivery. Use `assets/review-result.template.md` only for formal review; see [Execution Model](execution-model.md) and [Project Harness](project-harness.md).
