# Stage 5：Implement

在修改代码、配置、测试或项目文档时读取本文件。

## 目标

按照 Change Plan 完成最小必要修改，并维持项目事实、用户修改和质量门禁的一致性。

## 执行

1. 从最小可验证变更单元开始实施。
2. 保持每项修改与验收条件或必要工程约束的可追踪关系。
3. 同步新增行为所需的测试、配置和开发文档。
4. 在修改重叠区域前理解并保留用户已有工作。
5. 持续运行低成本、高信号的目标检查。
6. 发现接口、数据、范围或风险变化时，保存当前状态并返回 Design 或 Plan。
7. 将无关清理记录为独立候选 DevelopmentRun。
8. 提交、推送和外部写操作在授权触发点单独执行。

## Artifact

Implementation Change 由实际 diff、测试、配置和必要文档组成。运行状态记录：

- 已完成的计划项；
- 当前 revision 或工作区基线；
- 新发现问题；
- 计划差异及确认记录；
- 进入 Verify 所需命令。

## Implement Gate

- 当前计划项已完成或明确标记状态；
- 代码与配置能够进入验证；
- 新增行为具有对应测试或验证路径；
- 计划差异已经记录并确认；
- 用户修改和任务范围外内容保持完整。

实现可验证后进入 Verify。
