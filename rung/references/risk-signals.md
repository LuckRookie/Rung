# 工作类型、风险信号与 Profile 选择

在 DevelopmentRun 开始、影响范围扩大或用户请求调整流程深度时读取本文件。

## 工作类型

| 类型 | 主要判断 |
|---|---|
| Greenfield | 目标、项目骨架、技术选型与首个 Release |
| Feature | 用户可见行为、接口、数据和回归范围 |
| Bugfix | 复现证据、根因、回归测试和影响范围 |
| Refactor | 行为保持边界、结构收益和特征测试 |
| Migration | 当前状态、目标状态、兼容窗口、顺序和回退 |
| Dependency | API 变化、安全通告、锁文件、构建与兼容性 |
| Docs/Config | 文档或配置与实际行为的一致性 |
| Release-only | 已有实现的版本、证据、制品和发布信息完整性 |

## 初始 Profile

- **Lite**：影响局部、接口稳定、回退简单、验证路径清楚。
- **Standard**：普通 Feature、多文件修改、新模块、常规依赖升级或中等重构。
- **Strict**：新项目、核心架构、公共接口、安全、隐私、持久化数据、跨模块依赖或发布链路发生变化。

## 升级信号

出现任一信号时重新评估并建议升级：

- 公共 API、协议、文件格式或数据库 Schema 变化；
- 认证、授权、加密、密钥或敏感数据处理变化；
- 多个核心模块或依赖方向变化；
- 迁移需要兼容窗口、分阶段执行或回退；
- 构建、打包、签名或发布流程变化；
- 关键依赖被删除、替换或跨越主要版本；
- 影响范围仍存在重大未知；
- 现有测试对兼容性提供的证据有限；
- 用户修改与计划变更在同一区域重叠。

用户请求降低 Profile 时，记录：原 Profile、目标 Profile、减少的 Artifact 或检查、残余风险、用户确认。

## Verification Tier

| Tier | 目标 | 常见检查 |
|---|---|---|
| 0 | 快速发现明显错误 | 格式、语法、目标文件、smoke test |
| 1 | 证明局部模块行为 | 静态检查、单元测试、模块测试 |
| 2 | 证明跨模块兼容 | 集成、契约、构建、安全与依赖检查 |
| 3 | 证明完整发布准备 | 完整测试矩阵、端到端、打包、Release Gate |

Lite 通常从 Tier 0–1 开始，Standard 从 Tier 1–2 开始，Strict 从 Tier 2–3 开始。实际风险决定最终 Tier。
