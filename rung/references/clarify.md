# Clarify Card

Read when the user and Agent need to develop a consequential project or change decision together.

## Operate

- Use Inspect and Design for feasible directions. Read [Project Model](project-model.md) when meaning, fit, or evolution affects the choice; read [Design Exploration](design-exploration.md) when materially different paths leave it under-supported.
- Present the issue, recommendation, immediate consequence, development impact, and reversibility in plain language. Keep technical detail available on request.
- Incorporate the user's choice. When the user delegates an in-scope choice, record that scope and let the Primary Agent act as project designer; human-facing design receives UX attention.
- Ask only when a choice changes product meaning, material scope, accepted risk, durable data, or an authorization boundary.

Stop when consequential choices have an owner and the proposal supports the next action. Output accepted decisions, delegated authority, assumptions, and open choices.

Keep ordinary decisions in the session. Persist in an owning project fact or `assets/development-brief.template.md` when contracts, recovery, multiple executors, or formal review need it. Read [Execution Model](execution-model.md) for authority and persistence.
