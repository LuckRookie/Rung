# Stage 1：Clarify

在 DevelopmentRun 开始或新信息改变目标时读取本文件。

## 目标

把用户意图转换为足以设计、实施和验收的 Development Brief。

## 执行

1. 识别用户或调用方、当前问题和期望结果。
2. 把目标写成可观察的行为或交付物。
3. 定义任务范围、保持不变的区域和已知约束。
4. 为每项用户价值建立可验证的验收条件。
5. 记录兼容性、安全、时间、技术和外部系统约束。
6. 将可能改变产品方向、公共行为或数据含义的事项交给用户决定。
7. 对普通实现细节采用项目事实和当前 Profile 允许的工程判断。

## Artifact

使用 `assets/development-brief.template.md`，或更新项目已有 Requirements。Development Brief 至少包含：

- 问题与背景；
- 目标用户或调用方；
- 目标与范围；
- 验收条件；
- 约束；
- 开放问题与决策记录。

## Clarify Gate

- 目标、范围和验收条件相互一致；
- 每项验收条件具有观察或验证方式；
- 重大方向性假设获得用户确认；
- 开放问题已经解决，或明确标注为后续阶段可接受的输入。

Gate 通过后进入 Inspect。项目事实推翻需求假设时返回本阶段更新 Brief。
